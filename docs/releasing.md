# 测试版发布流程

当前定位为实验性家庭工具，不保证未列出的设备兼容。公开源码、GitHub Release 和应用商城上架是独立步骤。

## 发布前

1. 在独立目录从待发布源码构建两个 APK，运行 `python tools/check.py`，不允许跳过测试。GitHub Actions 必须通过。
2. 用正式签名构建；妥善备份签名密钥和密码，禁止上传仓库。CI 的临时签名不能用于现有用户升级。
3. 审查当前源码及全部待公开历史，排除凭据、设备信息、媒体、固件、日志和本地开发记录。`.gitignore` 不是已经提交内容的安全证明。
   同时检查提交作者／提交者邮箱、PR 预览引用、Issue／PR 正文与评论、Actions 日志及运行元数据、产物、缓存和 Release 附件。运行 `python tools/check-public-metadata.py` 检查邮箱；该脚本和 Gitleaks 均不能替代 GitHub 平台侧审查。
4. 完成下表中的相关实机检查。无法测试的能力明确标注未验证，不用推算或模拟结果替代。
5. 更新 README、CHANGELOG、截图和兼容范围；截图使用演示数据。无适合公开的截图时不要提交私人截图。

## 实机检查

| 场景 | 手机受控端 | 盒子受控端 |
| --- | --- | --- |
| 首次配对、拒绝、关闭配对、撤销已配对设备 | 需验证 | 需验证 |
| 控制端断开／忘记、地址变化重连 | 需验证 | 需验证 |
| 屏幕方向、点击、长按、滑动、停止画面传输 | 需验证 | 需验证 |
| 播放／暂停／前后曲、小组件与下拉按钮 | 需验证 | 需验证 |
| 重启后后台启动、停止服务及升级恢复 | 需验证 | 需验证 |
| 充电保护与恢复系统控制 | 按已适配驱动验证 | 不适用 |
| HDMI 关闭、CEC、实体键、待机与音乐连续性 | 不适用 | 按具体固件验证 |

记录版本、设备、固件、步骤、观察结果和未测边界。已知适配对象是 Redmi Note 9 Pro 与 HK1 RBOX K8 / RK3528；这不是上述每项均已在当前候选版本重新验证的声明。

音频验收还应包含 PCM／DSD 自动切歌及不同录音响度的变化。目前音量突变反馈尚未查明，USB 独占音量上限未验证；不得将测试通过描述为 bit-perfect 或听音安全认证。

## 发布产物

手动创建 GitHub **Pre-release**，提供正式签名的播放器 APK；故障记录 APK 是独立可选工具。附 SHA256 清单、安装与升级说明、已知问题和实测范围。不要把 CI 临时签名产物当作升级包。

```powershell
Get-FileHash outputs/*.apk -Algorithm SHA256
```

先完成可审阅的提交和检查，再由维护者决定是否将仓库改为公开以及发布版本。发布后保留问题反馈入口；没有维护能力时应明确暂停维护，而非承诺持续支持。
