# 安装、升级与移除

## 安装前

- 控制端无需 ROOT；受控端必须有有效 ROOT。不要为试用本项目刷写未知固件或解除设备安全限制。
- 同一 APK 提供控制和受控两种模式；独立“系统故障记录”是可选工具，听歌和远控不依赖它。
- 当前源码最低安装版本 Android 8，目标 API 32；这只是声明的安装范围，不是每个版本均已验证。已适配设备见 README，ROOT、充电驱动、HDMI 等能力取决于固件。
- 当前没有正式 Release。自行构建时按 README 配置 JDK 与 SDK，妥善保存生成的签名密钥和密码。

## 第一次使用

1. 在受控设备安装播放器，选择受控模式，点击“启动／恢复服务”并在 ROOT 管理器中允许该应用。
2. 在受控端本机选择已安装的音乐 APP，先手动完成登录、USB 授权和可播放曲目准备。不要把音乐账号、密码或验证码交给控制端。
3. 需要随时响应时，在系统中允许自启动和后台运行，将应用省电设为无限制。不同厂商设置路径不同；这些设置不保证系统深度休眠时网络可达。
4. 在受控端临时开启配对，从控制端或 PC 工具搜索，核对六位码并在受控端批准。配对后可关闭新配对入口。
5. 验证屏幕操作和播放，再按设备情况配置电源策略。盒子待机、关闭 HDMI、停止画面传输是不同操作。

不用为了正常控制长期开放系统 ADB。关闭发现会影响地址变动后的自动重连，已知地址的直接连接不受影响。

## 升级

使用同一签名覆盖安装，保留配对与本机配置。受控端升级后在本机点击“启动／恢复服务”更新 ROOT 助手。不要使用 CI 临时签名 APK 覆盖正式安装；若提示签名不一致，先确认包来源和签名，不要直接卸载。

当前没有自动更新机制。升级前记录版本及本机设置；跨版本迁移应先在备用设备验证。

## 停用与卸载

1. 在受控端点击“停止受控服务”，确认服务停止，手机由系统恢复充电管理，再卸载 APK。直接卸载 APK 不会自动清除 ROOT 目录。
2. 不再使用的控制端可在受控端撤销授权；控制端“忘记”仅删除该端本地档案，不能代替撤销。
3. ROOT 助手保留在 `/data/adb/living-player`，Magisk 启动脚本可能位于 `/data/adb/service.d/living-player.sh`。只有在确认服务已停止、不再需要配对和配置后，才由熟悉 ROOT 的用户移除这两个明确属于播放器的路径。不要删除整个 `/data/adb` 或 `service.d`。
4. 故障记录器需在它自己的 APP 中停止；播放器停用不会停止故障记录器。卸载与日志清理见 [独立系统故障记录](system-diagnostics.md)。

本项目尚未提供 ROOT 残留的一键清理器。不确定服务或充电控制是否已恢复时，先保留 APP 和相关目录，不盲目删文件。
